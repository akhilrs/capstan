01 One vocabulary for four surfaces

Every surface says a member's or a set's state with the same word and the same glyph. Colour is added on top and never carries the state alone: the word is always there, and where only a glyph fits (the strip) the glyph's shape differs per state and the row's sentence says the counts. The feed's merged is never shown as "merged": it means merged into the integration branch, so it reads built, as the approved Mac inspector already does.

The dash STATE column uses the single word (building, built, partly in main, in main, conflicted, failed, discarded). Markers that are not states: Next (the first live member not in main), Review subject (underline under the glyph in a strip, a tag in rows), attempt 2 (after one redo; nothing before a redo).

Truncation and overflow

Repo names up to 32 characters: cut in the middle where a column is fixed, whole where the row wraps or has room

32 repos (the limit of a set): the strip shows a fixed number of glyphs, then "+n"; the count sentence always covers every repo

cstan, dash 100+ columns   ●●●●●○○○○◌◌◌ +20  5 of 32 in main
dash 80 columns            ●●●●●○○○ +24  5 of 32 in main
Mac inbox row              12 glyphs, then +20
iPhone inbox row           8 glyphs, then +24  (VoiceOver: "and 24 more repos")

The glyphs shown are always the first ones in merge order, so the next repo is in view while fewer than 12 are in main; once more are in main, the strip starts 2 before the next repo and gains a leading "+n" (+9 ●●○○○…). Member lists (Mac detail, sheets, dash selected area) scroll; the next repo is scrolled into view when the list opens.
