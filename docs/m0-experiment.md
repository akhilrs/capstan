# M0 experiment contract

## Authority

`fixtures/m0-fixtures.json` is authoritative for fixture bytes and source revisions. This document is authoritative for experiment policy. `decisions/DEC-001-foundation.md` is authoritative for the foundation decision. Revisions are append-only after measured runs.

## Frozen runtime boundary

Measured runs require Linux x64, a Docker image pinned by digest, Node 24.6.0, OMP 18.3.1, Herdr 0.9.0, `PATH=/usr/local/bin:/usr/bin:/bin`, `HOME=<run-root>/home`, `LC_ALL=C`, `LANG=C`, `TZ=UTC`, `TMPDIR=<run-root>/tmp`, and `umask 077`. Fixture materialization applies the manifest mode after each file write. Candidate scanner mode policy permits only 0600, 0644, and 0755. A declared executable candidate path must be 0755 before verification. The provider-variable names are recorded without values. The network allowlist contains only authenticated loopback controller IPC and exact provider hosts and ports proven in M1. DNS and redirects cannot widen it.
Fixture manifests are strict UTF-8 RFC 8259 JSON without BOM or duplicate keys. Objects reject unknown fields and require only their schema-required keys. Task IDs and each task’s file paths are unique. Commands are JSON argv arrays executed without a shell. JSONL has the exact record and line rules in its fixture prompt; an invalid UTF-8 byte sequence is malformed at its first line. Safe-integer accumulation overflow is malformed at the overflowing record’s line. Output is JSON.stringify-compatible compact UTF-8 JSON, with category ordering by Unicode code point. Materializers reject invalid base64, paths, modes, hashes, symlinks, and any byte mismatch before a candidate starts.
Manifest schema: root requires `schema`, `serialization`, `environment`, and `tasks` only. Every task requires `id`, `prompt`, `permitted_paths`, `files`, `source_revision`, `command`, `valid_stdin`, `valid_stdout`, `valid_stderr`, `valid_exit`, `malformed_stdin`, `malformed_stdout`, `malformed_stderr`, `malformed_exit`, `malformed_applicable`, `regression_cases`, and `reset`; it permits `malformed_regression_cases` only when `malformed_applicable` is true. A file requires `path`, `mode`, and `base64`. Each regression case requires `stdout`, `stderr`, and `exit`; it may override `command` as an argv array and one mutually exclusive input override: `stdin` as UTF-8 JSON text or `stdin_base64` as arbitrary input bytes. Absent `stdin` and `stdin_base64` mean empty stdin, including command overrides. The primary command owns `valid_stdin`.
Wire grammar: root `schema` is the literal `capstan.m0-fixtures.v1`; `environment` has exactly `node` string `24.6.0`, `locale` string `C`, `timezone` string `UTC`, and `newline` string `LF`; `serialization` has exactly the declared keys and values in the manifest. IDs are nonempty ASCII `[a-z0-9-]+`; paths are nonempty ASCII matching `path_pattern`, contain no NUL, and obey forbidden segments. Modes are exactly `0644` or `0755`; base64 is canonical padded RFC4648; `source_revision` is lowercase 64-hex SHA-256. All manifest strings except `stdin_base64` must be Unicode scalar-value strings with no NUL; `command` is a nonempty argv string array; text input/output fields are strings; exits are integers 0–255; boolean fields are JSON booleans; array fields contain only their declared object variant. SHA-256 source revision is the lowercase hex digest of `concat(for each file sorted by ASCII path ascending: UTF-8(path) || 0x00 || ASCII(mode) || 0x00 || ASCII(decimal byte length) || 0x00 || decoded bytes)`. No separator or trailer follows the final file.




M1 runs ten clean probes for acknowledgement and ten for each declared long-running tool. Each acknowledgement probe spans launch through durable receipt. Each progress sample is the greatest silence interval over the full assignment lifecycle: acknowledgement to first qualifying observation, between observations, and final observation to accepted completion. A qualifying observation has the active assignment, attempt, generation, command ID, and an immutable evidence reference. It is exactly an authorized declared action that advances the assignment’s required state: a new `tool_started` for the current next required action; a `tool_progress` event with a strictly increased completed-work counter; a `tool_completed` result that advances the next required action; or a controller-accepted assignment report that names a newly produced candidate or verification artifact. The controller deduplicates events by command ID and evidence identity. Repeated starts, failed/no-op actions, events for any other action, and reused evidence do not reset the silence timer.


Any failed or censored probe fails M1. Any acknowledgement sample over 120 seconds fails M1. Any progress-silence sample over 900 seconds fails M1. M1 also runs ten clean replacement probes, including at least one probe per relevant runtime whose container deliberately ignores graceful-stop signals and must be force-killed. Each probe measures monotonic time from assignment-capability revocation through stop, forced-kill fallback when needed, cgroup empty, writable mount removal, and a no-follow manifest scan with no mutation. Any replacement probe over 30 seconds, inability to force kill, retained mount, or mutation fails M1. The quiescence interval is `clamp(5s, 3*max(replacement sample), 30s)`. Otherwise acknowledgement deadline is `clamp(30s, 3*max(acknowledgement sample), 120s)`. Progress window is `clamp(120s, 3*max(progress-silence sample), 900s)`. Each maximum is over the ten successful monotonic samples for its matching property. M1 freezes raw samples, observation types, selected values, cgroup-empty evidence, mount-removal receipts, and manifest digests before qualification.

## Safety and containment

Each writer has a distinct Docker PID namespace and cgroup. Only its workspace and narrow bridge endpoint are writable. Controller state is unavailable or read-only. Worker environments exclude SSH agent, home, production, push, cloud, and deployment credentials.

Before replacement or inspection, the controller revokes the assignment capability; stops then kills the container; proves container and cgroup quiescence; removes the writable mount; and observes the M1 quiescence interval. Failure blocks the run. The scanner uses no-follow beneath-root traversal from trusted open directories and rejects symlinks, special files, mount points, hardlinks, unauthorized modes, unauthorized paths, and out-of-scope changes. Evidence is preserved before cleanup.

## Baseline configuration

The baseline is claw8 driving OMP 18.3.1 directly. It uses the same frozen prompt, fixture source revision, Node 24.6.0 container image digest, model/provider identifier and settings, tool policy, token/cost budget, environment, seed, run order, and cache policy as the matching Capstan run. Cost is the provider-reported monetary cost for all role or baseline sessions in USD. An intervention is one operator action that changes workflow routing, scope, runtime authority, or recovery. Inspection-only actions do not count. M1 records the exact immutable image digest, provider hosts/ports, model identifier, and provider settings in the run-policy manifest before measured runs. Their absence blocks qualification.

## Measurement

Each system runs each of the three frozen tasks three times. Each Capstan/baseline pair has the same task, source revision, fixture-manifest SHA-256 digest, exact `docs/m0-experiment.md` SHA-256 digest, `MVP_PLAN.md` SHA-256 digest, repetition index, prompt, model settings, budget, environment, seed, order, and cache policy. Failed and blocked runs remain recorded and are never replaced.
Each run-policy manifest records SHA-256 digests of the exact `MVP_PLAN.md` and `docs/m0-experiment.md` bytes used for its correctness gate and policy.

Record acceptance, safe block, false acceptance, duplicate writer, stale acceptance, lost handoff, unauthorized transition, elapsed time, tokens, cost, human interventions, dispatches, retries, replacements, and unknown usage. Correctness uses the hard gate in `MVP_PLAN.md`.

Efficiency demonstrated requires complete comparable accounting, all nine exact pairs accepted by both systems, and aggregate provider cost and aggregate human interventions computed as the sum over those nine pairs. Capstan aggregate cost must be no greater than baseline aggregate cost. Capstan aggregate interventions must be no greater than baseline aggregate interventions. One aggregate must be strictly lower. Any unknown cost makes cost accounting incomplete. Any unknown intervention makes intervention accounting incomplete. Efficiency regression requires complete pairs and accounting, no lower aggregate cost or interventions, and one higher aggregate. All other post-correctness outcomes are **correctness feasible, efficiency inconclusive**. No population claim is permitted.
