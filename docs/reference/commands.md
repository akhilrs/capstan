# `cstan` command reference

Back to the [README](../../README.md).

Checked against the `usage` string in `rust/crates/cstan/src/usage.rs` (run `cstan` with no arguments to print it), the `ROUTES` table in `rust/crates/daemon/src/handlers/mod.rs` and the handlers in `rust/crates/daemon/src/handlers/`. "Who" shows which credential the daemon accepts: operator (the key in `.capstan/`), agent (an agent's environment token), or either. Every routed command accepts `--json`.

Record ids (reports, reviews, integrations, messages, findings, prompt relays, operator proposals and grants, cleanups, and what `inspect` reads) may be given as a unique prefix of at least four characters, as in git. The daemon resolves the prefix before the command runs: a unique one becomes the full id, an ambiguous one is refused with the candidates listed, one shorter than four characters is refused when it would have matched, and an unknown one fails as it always did. An exact id always wins. Agent ids, plan ids and package ids are matched exactly.

### Project and daemon (operator)

| Command                                                     | Purpose                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cstan --version`, `-V`, `version`                          | Print `cstan <version>` and exit 0. Needs no daemon, `.capstan/` or git repo.                                                                                                                                                                                                                           |
| `cstan --help`, `-h`, `help`                                | Print the usage text to stdout and exit 0.                                                                                                                                                                                                                                                              |
| `cstan init [--git] [--track-config]`                       | Create `.capstan/`, a starter `capstan.toml` (the designer prompt is built in; no `roles/` folder) and the managed capstan block of `.gitignore` (`.capstan/`, `capstan.toml`, `capstan.toml~`; lines outside it are kept). `--track-config` leaves `capstan.toml` out of the block. `--git` also runs `git init` (only if the folder is not a repository) and commits the current files as `chore: initial commit` after listing them; without it git is never run or committed, and a missing repository or commit only prints a warning. |
| `cstan init --gitignore [--track-config]`                   | Only add or update the capstan block of `.gitignore` (and the local exclude backstop), in an initialized or uninitialized project; prints `Created`/`Added`/`Updated` the block or `The capstan block in .gitignore is current`. A file with two blocks or an unterminated one is refused (exit 3). Cannot be combined with `--git`. |
| `cstan start`                                               | Start the daemon and launch the PM. Refuses (exit 3) unless the project root is the top of a git work tree whose HEAD is a commit.                                                                                                                                                                      |
| `cstan stop`                                                | Stop the daemon.                                                                                                                                                                                                                                                                                        |
| `cstan ping`                                                | Check that the daemon answers and print `project <root>` and `ledger <path>` of the daemon reached (`--json`: `projectRoot`, `ledgerPath`; an older daemon prints `project unknown (older daemon)`).                                                                                                    |
| `cstan config check`                                        | Validate `capstan.toml` and print the resolved config (warnings on stderr).                                                                                                                                                                                                                             |
| `cstan config sync`                                         | Write role definitions into the ledger (daemon stopped).                                                                                                                                                                                                                                                |
| `cstan herdr-config`                                        | Print an optional Herdr `config.toml` snippet.                                                                                                                                                                                                                                                          |
| `cstan pm restart`                                          | Replace the PM session, seeded from the ledger.                                                                                                                                                                                                                                                         |
| `cstan resolve <message-id> retry\|skip\|cancel ["<note>"]` | Settle a blocked message.                                                                                                                                                                                                                                                                               |

`cstan daemon` is the internal command that `cstan start` runs in the background; you do not need to run it. `cstan assign` and `cstan ask` are listed in the usage string but answer `not_implemented` in this version.

### Look and read

| Command                                                     | Who            | Purpose                                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cstan status [--json] [--all]` / `--watch [--interval N]`  | either         | Project state; starts with the same `project` and `ledger` lines (`--json`: `controller: {pid, projectRoot, ledgerPath}`). The text lists the agents that are not ended or released, plus any ended agent that is lost, stalled or still holds a pane, one line each, with a count of the hidden ones; `--all` lists every agent ever started. Members that are empty are left out of the text. `--json` is always complete.                                                                                                                                                        |
| `cstan controllers [--json]` | any folder | Every controller running on this machine, found by scanning your processes for `cstan daemon` (so old builds and leftover processes show too). One line each: `PID`, `STATE`, `VERSION`, `UPTIME`, `CPU` (sampled over 0.2 s), `MEM` (resident), `AGENTS` (active) and `PROJECT` (home shown as `~`). `STATE` is `serving` when the controller answers on its project's socket, `not answering` when the process runs but does not (with `(no operator key)` or `(key refused)` when it could not be asked), and `orphaned` when its ledger or project was deleted or another process now serves the project (`(ledger deleted)`, `(project deleted)`, `(superseded by <pid>)`). `VERSION` is `?` and `AGENTS` is `-` for a build that cannot report them. `--json` prints an array of `{pid, state, note, version, uptimeSeconds, cpuPercent, memoryBytes, activeAgents, project}` with the full project path and null for what is unknown. Read-only: nothing is signalled or written. It asks each controller the `about` route (`ping` for an older build) with that project's own operator key, read from `.capstan/operator.key` after the daemon's ownership and mode checks, and ignores `CAPSTAN_SOCKET` and `CAPSTAN_TOKEN`. Only your own processes are listed. |
| `cstan inspect <id> [--json]`                               | operator       | One ledger record.                                                                                                                                                                                                                                                                |
| `cstan dash [--interval N] [--no-color] [--reduced-motion]` | operator       | Dashboard.                                                                                                                                                                                                                                                                        |
| `cstan inbox [<agent-id>]`                                  | either         | Agent (the PM too): delivers and prints all its waiting mail, oldest first, with each action-needed message under an `[ACTION NEEDED]` line; ack each in any order. Info messages are listed after them in an `info (N, acknowledged automatically)` block (id, sender, body) and are acknowledged by the delivery itself (`[messages] auto_ack_info`); `--json` adds `actionNeeded` per message, `actionNeededCount`, `info` and `infoCount`. A client that does not send `--digest` gets info in `messages`, unacknowledged. Operator: an agent's mailbox (id required). |
| `cstan inbox --hook`                                        | agent          | Read-only, silent when nothing waits. Used by the Claude PostToolUse hook; prints hook JSON when mail that wakes the agent waits (info-only mail stays silent; the stderr `notice:` line follows the same rule and adds `(+N info)`), and always exits 0 (silent too when the `CAPSTAN_*` variables are missing).                                                                                          |
| `cstan observe <agent-id> [lines]`                          | PM, Supervisor | Another agent's recent screen.                                                                                                                                                                                                                                                    |

### Messaging and workers

| Command                                                              | Who    | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `cstan send [--info\|--action] <agent-id\|@pm> "<text>"`             | either | Queue a message. `--action` marks it action-needed: it wakes the PM, the recipient's inbox prints `[ACTION NEEDED]` above it and the unread notice counts it. `--info` is for awareness: it does not wake the PM, the next `cstan inbox` shows it in a compact info block and acknowledges it automatically. Both flags together are refused. With neither, `[messages] send_default` decides (default `action`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `cstan wait`                                                         | agent  | Block for new messages (up to the host wait timeout). Returns when mail that wakes the agent under the `[messages]` wake policy is pending (action mail; info only under `wake = "all"` or after `info_wake_after_seconds`), or on timeout; then delivers and prints all pending mail like `cstan inbox` (action mail, then the info block). The wait itself pulls nothing, so a superseded or aborted wait leaves mail queued.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `cstan ack <message-id>... \| --all-read`                            | agent  | Acknowledge messages. Several ids are acknowledged together, and one invalid id refuses all of them. `--all-read` acknowledges every message already shown to you (not mail queued since your last inbox). Prints `<id>: <state>` for each.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `cstan spawn <role> [--task <ref>] [--type <type>] [--title <text>]` | either | Start a worker on a new branch. `--task` is `<plan-id>/<package-id>` or a requirement ref id and names the branch `<type>/<task-id>-<slug>`; `--type` is one of `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`; `--title` sets the slug (whitespace is folded, control characters are refused, and it is cut to 200 characters). The task and title are stored with the worker's pane row and shown by the operator's `cstan status` (`panes[].taskRef`, `panes[].taskTitle`, and `activeTasks`: active plans with their packages, and requirements an active worker holds; capped at 10 plans, 30 packages per plan and 20 requirements, with `truncated` set when a cap cut rows). `cstan replace` carries the predecessor's task and title to the successor; a predecessor whose pane row is already gone yields none. Without `--task` the branch is `chore/<agent-id>-<slug>`. Fails with `git_requirement` (naming the missing repository or commit and the fix) when the project is not a git repository with a commit. See [Branches, commits and releases](workflow.md#branches-commits-and-releases). Fails with `role_limit: <ids> is already active (max_active = N)` when the role already has `max_active` active agents (a Supervisor role defaults to 1); nothing is started and no agent is released. |
| `cstan release <agent-id>`                                           | either | End a worker, free its pane and worktree.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `cstan replace <agent-id>` | either | Replace a lost or stuck worker. The release and the start of the successor run in one launcher turn, so the supervision tick cannot start an agent of the role in between. If the ledger already holds a replacement of the agent, or the agent is ended, its role has `max_active = 1` and the one active agent of the role was created after it ended, nothing is started: the answer is `state: already_replaced` with `agentId: <successor>` (exit status 0) and the replacement is recorded (packages, links and a plan's architect follow the successor). Roles with `max_active` above 1 or without a limit never adopt an agent; they start a new one, which fails with `role_limit` when the limit is reached. |
| `cstan pause [<agent-id>] --reason "<text>" [--interrupt]`           | either | Hold one agent, or the whole run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `cstan resume [<agent-id>] --reason "<text>"`                        | either | Release a pause.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

`cstan pause` and `cstan resume` are for the operator and the active PM; a worker gets `forbidden`. `--reason "<text>"` (1 to 500 characters) is required. Without an agent id they act on the whole run, with one on that agent (which must be active; a PM may not pause itself). A double pause or a resume of something not paused is refused. `--interrupt` (pause only) also sends exactly one `Esc` to each worker Herdr shows working (never the PM) and needs `[prompt_relay] enabled = true`; without it nothing is paused and the command answers `not_configured`. The answer lists the agents that got the Esc. See [Pause and resume](workflow.md#pause-and-resume).

### Delivery flow

| Command                                                   | Who                 | Purpose                                                                                                                                  |
| --------------------------------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `cstan report <commit> "<summary>"`                       | Developer, Verifier | Report a finished commit (full 40-character id). Refused, with nothing recorded, for the reasons in [Report refusals](#report-refusals). |
| `cstan request-review <report-id\|integration-id> [role]` | PM                  | Start an independent review. Reuses the plan's warm reviewer when there is one (see below).                                              |
| `cstan review pass\|findings "<text>"`                    | Verifier            | Answer a review request once.                                                                                                            |
| `cstan integrate <report-id>...`                          | PM or operator      | Merge reviewed reports onto an integration branch.                                                                                       |
| `cstan integrate confirm\|discard <integration-id>`       | PM or operator      | Settle a merged integration.                                                                                                             |
| `cstan verify <report-or-integration-id>`                 | anyone              | Queue a gate run (the `[verify]` commands) at the commit of the report or integration and print the run id. A run already queued, running or passed for the same commit and commands is answered as it is (`existing`), not queued again. |
| `cstan verify show <run-id>`                              | anyone              | State, subject, commit, commands, exit code, failed step (1-based, with its command), duration, log path and the tail of the output (the last 40 lines of what the daemon keeps; the full log is at the path). |
| `cstan verify list [<subject-id>]`                        | anyone              | The runs of a report or integration, or the latest runs, one line each. |
| `cstan verify cancel <run-id>`                            | anyone              | Cancel a queued or running run. |
| `cstan design approve <plan-id>/<package-id> --link <url-or-path> --asked-user "<what the user said>"` | PM or operator | Record the user's approval of the latest report of a design package (`"design": true` in the plan). Packages that depend on it can then be assigned. |
| `cstan design changes <plan-id>/<package-id> --asked-user "<what the user asked to change>" [--link <url>]` | PM or operator | Record that the user wants changes. The package's assignee is sent a message with the link and the user's words, to revise, commit (amend) and report again; the answer lists dependent packages that are already assigned. |
| `cstan design guide [<topic>]`                            | anyone              | Print a built-in designer guidance topic exactly as stored, or list the topics (`main`, `rules`, `directions-product`, `directions-brand`, `redesign`, `proposal`, `record`; one `<topic>  <description>` line each). Runs locally: no daemon, project or agent token, and it writes nothing. An unknown topic or any extra argument or flag (including `--json`) prints the topic list on stderr and exits 2, except `--help` or `-h`, which prints this entry. |
| `cstan design show <plan-id>[/<package-id>]`              | anyone              | The design packages of a plan: latest report, whether the gate is open and every decision. |
| `cstan cleanup --dry-run`                                 | PM or operator      | List the local branches in three groups: **landed**, **unlanded** and **active or protected**. Each shows the branch, its commit (sha), its worktree and the reason. Reads only; no ref changes. |
| `cstan cleanup`                                           | PM or operator      | Record an offer of the landed branches (and the unlanded ones when `[cleanup] include_unlanded = true`) and print its cleanup id. Nothing is deleted. A newer offer supersedes an older open one. |
| `cstan cleanup apply <cleanup-id> [<branch>...]`          | PM or operator      | Delete the landed branches of the offer, or exactly the branches named. Prints each deleted branch with its sha and the `git branch <name> <sha>` line that restores it, and each skipped branch with the reason. |
| `cstan cleanup decline <cleanup-id>`                      | PM or operator      | Decline an offer. Nothing is deleted. |

**Request-review.** The answer is `{ reviewId, round, reviewerAgentId, reviewerRole, commit, state, reviewerState, reviewerReused }`. `reviewerReused` is `true` when the plan's warm reviewer was moved to the commit instead of a fresh reviewer being spawned (`reviewerState` is then `reused`). Reuse needs `[review] warm_reviewer` (default on; see the `[review]` section in [Configuration](configuration.md)); the reviewer is kept after a verdict and released on `plan signoff`, `plan cancel`, after `idle_minutes` idle, after `max_reviews` reviews, when `cstan spawn` needs its slot (`role_limit` or `worker_limit`: the least recently used idle one is ended and the spawn tried once more) and when a restart finds its agent gone. See [Workflow](workflow.md) for the brief, which names the diff scope, the package's owned paths and acceptance, and the passed gate.

**Design approval.** `cstan design approve` and `design changes` refuse a package that is not a design package, a cancelled package, a package with no report yet, an empty `--asked-user` and, for `approve`, a missing `--link`; any caller but the PM or the operator is refused. A decision is about the package's latest report and is never edited; a newer report needs a new decision. With `--json`, `approve` and `changes` print `{ planId, packageId, decision, reportId, link, askedUser, decidedAt, messageId, assignedDependents }`. `plan show` gives each package `design` and, for a design package, `designDecision { decision, link, reportId, decidedAt }` or `null`. See [Workflow](workflow.md).

**Verify.** `cstan verify` needs a `[verify]` section (see [Configuration](configuration.md#verify)); the daemon runs the configured commands in a scratch worktree at the commit and records the result; without the section it answers `verify_not_configured`. The client waits up to 10 minutes for the answer. With `--json`, a run is `{ runId, sequence, subjectKind, subjectId, commitSha, commands, commandsSha, trigger, requestedBy, state, queuedAt, startedAt, finishedAt, exitCode, failedStep, durationMs, outputTail, outputTruncated, logPath }` (plus `existing: true` on a repeated queue request); `verify list` prints `{ runs }` and `verify cancel` `{ runId, state }`. States are `queued`, `running`, `passed`, `failed`, `timeout`, `error`, `interrupted` and `cancelled`. `request-review` and `integrate` refuse with `verify_required` (exit code 3, like other gate refusals) when `[verify] require` names them and no passed run matches the commit and commands; the message names the `cstan verify <id>` to run. The operator's `cstan status` gains a `verify` member `{ active, recent }` (runs without their output tail; at most 5 recent) and prints `verify active:` and `verify recent:` lines, one run each with state, commit and age or duration. `plan show --brief` ends each package row with the latest gate of its report: `gate passed 14m02s`, `gate failed step 2`, `gate running`, `gate queued`, `gate timed out`, or `no gate`; without a `verify` member on the row (an older daemon) the row is as before.

**Cleanup.** A branch is *landed* when its tip is the commit of an accepted report that a confirmed integration holds, and *landed by content* when no report says so but every change it made is in HEAD (the offer lists these with the landed ones; `apply` without names deletes only the *landed* ones). Everything else is *unlanded*. These are never candidates: the project's main branch and the one checked out, a branch an active agent works on, the branch of an integration that is not confirmed or discarded, a branch checked out in a worktree no ended agent owns, and a branch whose worktree has uncommitted changes. `apply` checks every branch again when it runs: the tip must still be the offered commit and the branch must still be safe; otherwise it is skipped with a reason (`tip_moved`, `now_protected`, `class_changed`, `budget`, ...). A branch of an ended agent has its clean worktree removed first (unless `[cleanup] worktrees = "keep"` on an automatic run). Each deletion is recorded in the ledger, and the output gives the `git branch <name> <sha>` line that brings the branch back. `cleanup` is refused while the run is paused (`paused`) and while an integration is running (`integration_running`), and by every caller but the PM and the operator. Only local branches are looked at; remote branches never. The ledger records offers and deletions; see [Configuration](configuration.md#cleanup) for the `[cleanup]` section.

### Tool caches

Needs a `[cache]` section in `capstan.toml` (see [Configuration](configuration.md#cache)). `cstan cache status` works for anyone and without the daemon: it reads `capstan.toml` and `.capstan/project.json`. `prune` and `clear` run in the daemon when you are an agent (`CAPSTAN_TOKEN` and `CAPSTAN_SOCKET` set), and the daemon lets only the PM and the operator through; without an agent environment they run locally and the daemon need not be running. The guard prevents mistakes; it is not a security boundary, because a shell without those variables runs the local path. The worst case is that a cache that can be rebuilt is cleared.

| Command                                         | Who            | Purpose |
| ----------------------------------------------- | -------------- | ------- |
| `cstan cache status [--json]`                   | anyone         | One row per entry: enabled, or the reason it is off, mode, size, files, last use, root and scope. The sizes are measured now (the walk is bounded). Entries from `presets`, `detect` and `[cache.entries.*]` are listed, and `setup` when `[cache.setup_reuse]` is set. |
| `cstan cache prune [<entry>...] [--dry-run]`    | PM or operator | Run the tools' own prune commands, then the age and size limits (`max_age_days`, `max_size_gb`, an entry's own `max_size_gb`): expired entries go first, then the least recently used until the total is under the cap. Entries are removed only while no linked git worktree exists (no agent is working); otherwise the answer lists what would be removed. With names, only those entries are pruned. `--dry-run` runs nothing and removes nothing: it lists the commands that would run and the entries that would go. |
| `cstan cache clear <entry>...\|--all [--force]` | PM or operator | Remove the named entries (`setup/<key>` names one setup snapshot) or all of them. Refused while a linked worktree exists unless `--force`, and always refused for `scope = "user"` (the store is shared with other projects) unless `--force`. An entry's stop commands (for example `sccache --stop-server`) run before it is removed. |

`cstan cache status --json` prints `{ schemaVersion, root, scope, maxBytes, maxAgeDays, totalBytes, partial, measuredAt, entries: [{ name, origin, enabled, reason, mode, bytes, files, lastUsedAt, partial, dir }], setupSnapshots: [{ key, bytes, files, lastUsedAt }], warnings }`. `prune --json` prints `{ dryRun, idle, commands, wouldRun, cleared, wouldClear, totalBefore, totalAfter, partial, errors }`; `clear --json` prints `{ cleared, stopCommands, errors, totalBytes }`. After every prune or clear the sizes are measured again and the manifest rewritten, so `status` shows what is on disk.

Prune and stop commands run through `sh -c` in the entry's directory with a timeout and an environment of only `PATH`, `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_ALL`, `TERM`, `TMPDIR` and the entry's own variables; their output is sanitised like setup commands'.

The daemon also keeps the caches in shape on its own. When it starts it removes what a killed prune or clear left behind (the `.trash` directory and leftover temporary files). Then, off the controller's main thread, it measures and prunes every 6 hours (the first run comes at the latest 6 hours after the last measurement in the manifest, and soon after start when that measurement was over the cap), and writes the manifest. The operator's `cstan status` gains a `cache` member read from that manifest (status never walks the disk): `{ root, scope, entries: [{ name, enabled, reason, bytes, lastUsedAt }], totalBytes, maxBytes, measuredAt, warnings }`, with `bytes`, `totalBytes` and `measuredAt` null before the first measurement. The text status prints one line, for example `cache: rust off (sccache is not on the agent PATH), python 1.2 GB; total 1.2 of 20 GB, measured 4m ago`. Without `[cache]` there is no member and no line.

### Prompt relay (with `[prompt_relay] enabled = true`)

| Command                                                                                                                   | Who       | Purpose                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cstan prompt show <agent-id>`                                                                                            | active PM | Capture a blocked worker's permission prompt, or an unrecognised blocking dialog (Esc only), with options and hash.                                                    |
| `cstan prompt answer <relay-id> --hash <hash12> option <n> [--session auto=60\|auto=session\|auto=<n>]\|esc\|text <text>` | active PM | Type the answer the user chose (`--session` opens an auto-approve window, for an allow-once option only); a dialog relay takes `esc` only and reports `inputReadable`. |

### Operator (with `[operator] enabled = true`)

| Command                                                                          | Who                        | Purpose                                              |
| -------------------------------------------------------------------------------- | -------------------------- | ---------------------------------------------------- |
| `cstan op propose "<command>" "<reason>"`                                        | Operator                   | Propose one shell command. A command that runs `cstan stop` or `cstan restart` (alone or in a `&&`, `;`, `\|` chain or subshell) is refused with `controller_stop_refused`: use `--restart`. The check covers the obvious forms only; `eval`, `sh -c` quoting, aliases and scripts are not seen; shell comments are not recognized (an apostrophe in a `#` comment can hide a later stop, and a stop in a trailing comment is refused); and after a `$(...)` or backtick substitution the rest of the command starts a fresh segment, so `echo $(pwd) cstan stop` is refused. |
| `cstan op propose --restart [--force] "<reason>"`                                | Operator                   | Propose a controller restart. The controller starts a detached helper in its own process group, so the restart survives the old controller's exit. |
| `cstan op decide <id> approve --hash <hash12> [--session exact\|prefix=<words>\|auto=60\|auto=session\|auto=<n>]` | PM | Approve a proposal, optionally with a session grant (kind `exact` or `prefix`) or an auto-approve window (`auto=`; `timed` was removed and gives `timed_grant_removed`). |
| `cstan op decide <id> deny ["<note>"]`                                           | PM or operator             | Deny a proposal.                                     |
| `cstan op show [<id>]` / `cstan op cancel <id>`                                  | see the Operator reference | Show proposals and runs / withdraw a proposal.       |
| `cstan op grants` / `cstan op revoke <grant-id>`                                 | PM or operator             | List session grants and the window (time left) / end one (grant or window).  |
| `cstan op full-auto on [<minutes>] --asked-user "<text>"`                        | PM                         | Switch every guard off for a limited time.           |
| `cstan op full-auto off` / `status`                                              | PM or operator             | Switch full auto off / show the time left.           |

See the [Operator reference](operator.md) for the rules behind each command.

Arguments may not be empty and may not contain invalid UTF-8. Put long text in a quoted heredoc so the shell does not expand it:

```sh
cstan send developer-1 "$(cat <<'EOF'
Task text here.
EOF
)"
```

## Report refusals

`cstan report` fails with `rejected` and records nothing when:

| Code              | Meaning and fix                                                                                                                                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `unread_messages` | A message queued before the commit is not acknowledged. Run `cstan inbox`, ack, report again.                                                                                                                    |
| `commit_message`  | A new commit since the base breaks a commit rule, or there are more than 200 new commits. Each violation is listed as `commit_message: <short-sha> "<subject>" breaks <rule>: <reason>` (up to five). Fix below. |
| `rate_limited`    | More than 10 reports a minute; wait and report once.                                                                                                                                                             |
| `report_limit`    | The agent reached its report limit.                                                                                                                                                                              |
| `report_rejected` | The controller's own check failed: the commit is missing, is the base or older, is not on the worker's branch, or the agent or its branch changed while it checked. The report is recorded as `rejected`.        |

The `<rule>` in a `commit_message` refusal is one of `subject-format` (not `<type>[(scope)][!]: <description>` with an allowed type), `body-separation` (no blank line after the subject), `claude-co-author` (a `Co-Authored-By` line naming Claude), `claude-session` (a `Claude-Session` line) or `claude-code-footer` (a "Generated with Claude Code" line). Merge commits skip the first two. The allowed types are `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `style` and `revert`; git's default `Revert "..."` subject must be reworded to `revert: ...`.

To fix a `commit_message` refusal: reword the commit (`git commit --amend` for the tip, `git rebase -i` and reword for an earlier one) and report the new full commit id; or put the work on a new branch (`git switch -c <new-branch> <base>`, cherry-pick, reword) and report from there. If the controller could not read the commits it answers `error` ("could not check the commit just now") and you report again.

## Releases

`scripts/release.sh` is run by the person who releases, from a clean checkout; it is not a `cstan` command. It is POSIX `sh` plus `tools/release`, a small Rust program (a separate cargo workspace) that reads the commit history, so it needs `cargo`. It follows [SemVer](https://semver.org) and [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/): it picks the next version from the commits since the last `v*` tag, updates `VERSION` and `CHANGELOG.md`, commits `chore(release): v<version>` and creates a local annotated tag. It builds nothing, and nothing is pushed or published: pushing the tag starts `.github/workflows/release.yml`.

| Option            | Effect                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------- |
| `--dry-run`       | Print the current and next version, the changelog section and the assets; change nothing. |
| `--version X.Y.Z` | Use this version instead of the computed one. It must be higher than the current version. |

It refuses to run with uncommitted tracked changes, when nothing releasable (`feat`, `fix`, `perf`, `revert` or a breaking change) came since the last tag, and when the tag already exists. If the files cannot be written it restores them and nothing is committed or tagged. If committing or tagging fails, it prints the undo steps: `git tag -d v<version>` and, only when the release commit was created, `git reset --hard HEAD~1`. Publish by pushing the commit and the tag: `git push origin HEAD v<version>`.

## Controller messages

Messages whose sender is `controller` start with one of these prefixes (`rust/crates/kernel/src/areas/`, `rust/crates/config/src/prompts.rs`):

| Prefix                            | Meaning                                                                                        |
| --------------------------------- | ---------------------------------------------------------------------------------------------- |
| `Verified report`                 | A report was accepted: the commit exists on that worker's branch. Not a review.                |
| `Review request`                  | To a reviewer: the commit (or integration) to review.                                          |
| `Review`                          | To the PM: the reviewer's verdict as recorded. The text inside is the reviewer's opinion.      |
| `Finding`                         | A supervisor raised, resolved, escalated or cancelled a finding.                               |
| `Delivery problem`                | A message to a worker is `unacked`, `expired` or `failed`; run the `cstan resolve` it names.   |
| `Agent stalled` / `Agent blocked` | A worker made no progress / waits at a prompt.                                                 |
| `Agent ... is lost`               | Herdr no longer finds the agent's pane or process (`(paused)` after the id when it is paused). |
| `The operator paused` / `resumed` | The operator paused or resumed the run or an agent; held messages follow the pause.            |
| `Plan <plan-id> approved`         | To the PM: the plan's packages, dependencies and order.                                        |
| `Plan <plan-id> needs attention`  | To the PM: the plan did not pass review, or the Architect was lost.                            |
| `Plan <plan-id> signed off`       | To the PM: the integration branch and commit the Architect signed off.                         |
| `You now own plan`                | To the new architect of a reassigned plan (`plan_handover`): state, live packages and the pending report, review and integration ids; read `cstan plan show <plan-id>`. |
| `The architect of plan`           | To a developer holding a package of a reassigned plan (`architect_changed`): questions now go to the new architect. |
| `Operator run <id> finished`      | A proposed command ran; the output tail is untrusted data.                                     |
| `Routine check`                   | To the Supervisor: do one watch pass.                                                          |

## Exit codes

From `EXIT` in `rust/crates/cstan/src/usage.rs`: `0` ok, `2` usage error, `3` invalid input or configuration, `4` blocked (the controller refused the request, for example `worker_limit`, or `cstan start` failed to launch), `5` runtime error.

## Foreign socket guard

When `CAPSTAN_SOCKET` is set, `cstan` finds the nearest ancestor of the working directory that holds a `.capstan/` directory. If `CAPSTAN_SOCKET` is not that project's `.capstan/state/control.sock`, every agent command (including `ping`, `status`, `inbox`, `wait`, `send` and `dash`) exits 2 naming both paths and sends nothing. `cstan inbox --hook` exits 0 silently without a request. Set `CAPSTAN_ALLOW_FOREIGN_SOCKET=1` to proceed anyway; one warning line is printed (the hook stays silent and still makes no request). Without a `.capstan/` ancestor, such as a worker worktree, nothing changes.
