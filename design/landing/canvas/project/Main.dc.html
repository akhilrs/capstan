You talk to one PM. It runs the crew.

Capstan turns a few Claude Code and Codex sessions into a delivery team. Each worker gets its own pane, worktree and branch; a controller verifies every report, and nothing reaches your main branch unless you merge it.

How a task moves

Completion is never guessed from terminal text. Every step is a fact in a SQLite ledger.

  1. You ask the PM. It picks a tier: small work goes straight to a developer, larger work to an Architect who splits it into packages.

  2. Workers build. Each commits on its own branch, never pushes or merges, and runs cstan report.

  3. Reviews are independent. A fresh reviewer starts at the reported commit; findings go back to the developer.

  4. Integration is mechanical. Reviewed reports are squashed onto an integration branch without touching your checkout.

  5. You merge. Then cstan integrate confirm tells the controller to clean up.

Then, in your repo

Needs git, Herdr for the panes, and Claude Code for the PM.

# starter capstan.toml and roles/
cstan init
# validate and print the resolved config
cstan config check
# controller up, PM launched in Herdr
cstan start
# optional: watch the team
cstan dash
  • Never pushesWorkers commit on capstan/<agent>-g<n>. You merge.
  • Verified reportsA report names a full commit id, checked against the worker's branch.
  • Prompt relayPermission prompts reach you through the PM, with the exact answer typed back.
  • Pause anythingHold one agent or the whole run; messages stay queued.
