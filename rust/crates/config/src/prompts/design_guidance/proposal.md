# Direction proposal template

Use one template for every direction (2 or 3 per proposal) so the user compares like with like. Fill every item; write "none" rather than skipping one.

1. Name: a catalog name, or the name plus a custom twist; the one-line idea and who it suits.
2. Why it fits: tie it to the four axis scores and to at least one constraint of the brief.
3. Fields, each filled (F16 only for Throwback):
F1: mood (three words, one-line idea)
F2: surface polarity
F3: accent discipline
F4: neutrals
F5: type roles and sizes per surface
F6: shape language
F7: depth strategy
F8: spacing unit and density per surface
F9: imagery role
F10: signature moves
F11: forbidden moves (3-6, testable)
F12: responsive plan
F13: state coverage
F14: fallbacks
F15: motion
F16: period variant (Throwback only)
4. Token list: every colour with its role, every type style, radius, spacing step and motion duration used in the artifact, each with a name and a value. This is the one place values are stated; every other item refers to token names (rule R1 checks it). When DESIGN.md exists, mark each token as existing, new or changed.
5. Trade-offs and risks: what the direction does badly, the cost to build and the accessibility risk. Then a rule check: pass or fail per rule group (Typography, Colour, Layout, Imagery, Copy, Motion, Components, Record, Accessibility), listing every deviation with its rule id and reason. Contrast ratios of the main colour pairs come from a computed check, not from the eye.
6. Artifact link and screenshot paths.

After the directions, add a recommendation (one direction) and the distinctness claim: "these differ on axes X and Y". The user's pick fixes the token list that goes into DESIGN.md when the package owns it (see `record`).
