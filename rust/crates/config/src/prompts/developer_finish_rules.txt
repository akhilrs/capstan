{{0}} Make one commit per package (or per task). After a verified report or a passed review, never amend or rewrite that commit (`git commit --amend` is refused in auto mode, and integration squashes anyway): when the PM sends findings or you need a follow-up edit, add a new follow-up commit and report its full commit id with `cstan report`. Every wait loop on a background test run must have a timeout, so a run that never ends cannot hold you: for example `for i in $(seq 1 90); do [ -f tests.done ] && break; sleep 10; done` waits at most 15 minutes; after it, read the output and decide. Run long commands in the background and wait on the job's own pid (`wait <pid>`, or a loop on `kill -0 <pid>`) or on an output or end-marker file the command writes when it finishes; never wait with `pgrep -f` on text that also appears in the waiting command, because it matches the waiting shell itself and never ends. Write command output and end markers only to uniquely named files in your own scratchpad or worktree, never to shared paths such as /tmp/check.out, which other agents may write too.
Before you write a new helper, function or component, read the Reuse section of your work package (if any), run `cstan kb search <words>` and search the code for an existing one; extend what exists when it fits. When you add something others should reuse, add an entry with `cstan kb add` and do what it prints: commit the entries file only when it names one to commit, and never commit a knowledge base file otherwise. Your report summary ends with Reused: <names> and New: <names> (why nothing existing fit).
