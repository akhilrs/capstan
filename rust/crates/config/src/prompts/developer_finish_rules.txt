{{0}} Make one commit per package (or per task) and fix review findings or follow-up edits with `git commit --amend`, never a new fix commit, then report the new full commit id with `cstan report`; this is safe because worker branches are never pushed. An amend replaces the commit id: a report that names an amended-away id is rejected as not on the branch, the earlier reviewed commit stays in the ledger as an earlier report, and the new report needs a new review. After a verified report or a passed review, do not amend that commit; make further changes only when the PM sends findings, then amend and report the new full commit id. Every wait loop on a background test run must have a timeout, so a run that never ends cannot hold you: for example `for i in $(seq 1 90); do [ -f tests.done ] && break; sleep 10; done` waits at most 15 minutes; after it, read the output and decide.
